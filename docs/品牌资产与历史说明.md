# 品牌资产与历史边界说明

> 目的：明确 Synth 改名后**哪些内容已改、哪些按约束保留、保留项如何处置**。
> 本文档是「当前事实」类文档，已在 [`文档权威索引.md`](文档权威索引.md) §二登记。

## 1. 结论先行

工作区**文本文件的旧品牌名残留为 0**，由 `scripts/check-brand-residuals.sh` 在 CI 中持续保证。仍可能看到旧名的地方只有三类：二进制资产内嵌文字、git 历史对象、以及按设计引用旧名的迁移/说明文档。

约束：本次不重绘图片、不改写二进制；仅把含旧名的文件名同步为 `synth-*`（例如 `ap-architecture.png` → `synth-architecture.png`）。

**已有的文本源均已改**：`synth/docs/synth-architecture.svg`、`synth/docs/synth-architecture-v7.3.html/.json` 等矢量/HTML 架构图在改名时已按文本替换完成，建议后续以这些文本源为准重新导出 PNG。

完整清单可用以下命令复核：

```bash
git ls-files '*.png' '*.prof' '*.wasm' | wc -l
```

| 项 | 状态 | 约束与理由 |

这属于**历史边界**，不是残留缺陷：文档、CI 门禁只约束当前工作区文本。

## 4. 评测语料等历史快照

`docs/evals/embedding-corpus-v1.json` 等评测语料内嵌了改名/修复前的部署文档片段（例如旧的 `cd synth && docker build -f Dockerfile.prod .` 命令）。这些是**评测基线输入**，按 `文档权威索引.md` §四「历史/归档文档」原则保留原样，不随当前文档同步更新；改动会使历史评测结果不可比。

## 5. 法律与归属

`LICENSE` 的版权行已随改名变为 `Copyright 2026 Synth Contributors`。Apache-2.0 第 4 条通常要求保留原始权利人的版权与署名声明；是否补注原始权利人，应由维护者/法务决定，而非由文本替换工具推断。本说明不替代法律意见。

## 6. 门禁

- 脚本：`scripts/check-brand-residuals.sh`
- CI：`.cnb.yml`「品牌名残留检查」stage、`.github/workflows/ci.yml` 的 `version-consistency` job
- 扫描范围：工作区全部文本文件，排除 `.git`、`.workbuddy-ai`、`.codebuddy`、`.thinkrail`、`node_modules`、`dist`、`coverage`
- 白名单（按设计引用旧名，故排除）：`docs/迁移到-Synth.md`、`scripts/migrate-to-synth.py`、`docs/品牌资产与历史说明.md`、脚本自身
- 检查模式：旧品牌名（任意大小写）、旧组织名、旧 CRD group、旧 `AP_` / `ap_` 前缀（含 `__AP_AGENT__` 与 `"…\nap_pool…"` 这类嵌入形态）、旧配置文件后缀 `.ap.yaml` / `.ap.json`、旧 `ap-` 前缀产物名（如 `ap-dataset-v1`）、旧 `ap/` 路径段（如 `cmd/ap/init.go`）
- 边界规则：`AP_` / `ap_` 只要求前一字符不是字母，因此 `\nap_pool`、`__AP_AGENT__`、`"ap_x"` 都会命中，而 `map_`、`cap_x`、`gap_y` 这类普通词不会；`APIKey`、`APPDATA`、`ROADMAP` 同理不命中
