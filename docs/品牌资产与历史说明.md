## 1. 结论先行

**仓库正文**（代码、配置、当前文档、CI 脚本、发布清单）的旧品牌名残留为 0，由 `scripts/check-brand-residuals.sh` 在 CI 中持续保证。仍能看到旧名的地方只有四类：二进制资产内嵌文字、git 历史对象、按设计引用旧名的迁移/说明文档、以及 **sha256 冻结的评测题面**（见 §4——它们的哈希登记在 `docs/evals/manifest.json`，改动即冻结门报警）。

## 4. 评测语料等历史快照（按冻结台账保留旧名）

评测语料的 sha256 登记在 `docs/evals/manifest.json` 与 `synth/docs/evals/v72/manifest.json`，由 `internal/eval` 的 `TestEvalRegistryFrozen` / `TestV72RegistryFrozen` 守门（「一经冻结不得修改，扩充走 `*-v2.json`」）。因此这三个文件中的旧品牌字样、旧 CLI 与旧路径引用**必须保留原样**：

| 文件 | 保留的旧名 | 原因 |
|---|---|---|
| `docs/evals/embedding-corpus-v1.json` | `agentprimordia/docs/AP-开发手册.md`、`ap init`、`AP_LLM_API_KEY` 等 chunk 文本与 `source` 路径 | 检索/召回基线，改文本即改嵌入，历史指标不可比 |
| `docs/evals/gap-tools-v1.json` | `gt-014` 题面 `encode:ap!` | 冻结题面，改一字即台账漂移 |
| `synth/docs/evals/v72/p4-intelligence.json` | 夹具里的 AWS region `"ap-east-1"` | 本就是亚太区域名，不是品牌，是改名假阳性 |

这三个文件已加入残留门白名单（§6）。另：

- `scripts/gen-eval-sets.py` 的 base32 夹具行同步保持 `("ap!", "M4QTEA====")`，否则重新生成的题面与冻结款不一致。`gt-014` 的断言值本身不是合法 base32（已知缺陷，登记在 `docs/evals/README.md`「已知题面缺陷」），修正走 `gap-tools-v2.json`。
- 其余评测计划文档（`docs/evals/plans/*.md`）不参与哈希冻结，仍按改名后口径书写。

## 6. 门禁

- 脚本：`scripts/check-brand-residuals.sh`
- CI：`.cnb.yml`「品牌名残留检查」stage、`.github/workflows/ci.yml` 的 `version-consistency` job
- 扫描范围：工作区全部文本文件，排除 `.git`、`.workbuddy-ai`、`.codebuddy`、`.thinkrail`、`node_modules`、`dist`、`coverage`
- 白名单（按设计引用旧名，故排除）：`docs/迁移到-Synth.md`、`scripts/migrate-to-synth.py`、`docs/品牌资产与历史说明.md`、脚本自身，以及三个冻结评测题面 `docs/evals/embedding-corpus-v1.json`、`docs/evals/gap-tools-v1.json`、`synth/docs/evals/v72/p4-intelligence.json`（理由见 §4）
- 检查模式：旧品牌名（任意大小写）、旧组织名、旧 CRD group、旧 `AP_` / `ap_` 前缀（含 `__AP_AGENT__` 与 `"…\nap_pool…"` 这类嵌入形态）、旧配置文件后缀 `.ap.yaml` / `.ap.json`、旧 `ap-` 前缀产物名（如 `ap-dataset-v1`）、旧 `ap/` 路径段（如 `cmd/ap/init.go`）
- 边界规则：`AP_` / `ap_` 只要求前一字符不是字母，因此 `\nap_pool`、`__AP_AGENT__`、`"ap_x"` 都会命中，而 `map_`、`cap_x`、`gap_y` 这类普通词不会；`APIKey`、`APPDATA`、`ROADMAP` 同理不命中
