# Synth v7.9.0 发布说明

**发布日期**：2026-11-08
**版本**：v7.9.0（改名发布：AgentPrimordia → Synth）

## 一句话

项目从 `AgentPrimordia`（组织 `Gleamseekers`）改名为 **Synth**（组织 `Mirelth`，仓库 `Mirelth/Mirelth-Synth`）：模块路径、`package` 名、CLI、配置契约、环境变量、指标前缀、CRD group 与全部分发身份一次换完，**不保留兼容别名层**。

> 为什么是 7.9.0 而不是 8.0.0：`/v7` 导入版本后缀保留，语义化主版本不变；改名破坏的是「路径与命名」，框架能力与行为契约未变。

## 你会得到什么

- **一套自洽的新身份**：`github.com/Mirelth/Mirelth-Synth/v7`、`package synth`、`synth` CLI、`.synth.yaml`、`SYNTH_*`、`synth_*` 指标、CRD `synth.dev`、`@mirelth/synth` / `mirelth-synth` / `ghcr.io/mirelth/mirelth-synth`。
- **有路径的迁移**：`docs/迁移到-Synth.md` 给出对照表、手工要点、验证清单与回滚；`scripts/migrate-to-synth.py` 默认 dry-run，一条命令改完模块路径、包名、CLI、配置名与环境变量前缀。裸词 `AP` / `ap` 不自动改写（CAP 的 Availability、下游局部变量都会被误伤），只列进人工确认清单。
- **不回潮的门禁**：`scripts/check-brand-residuals.sh` 接入 CI，旧品牌名 / 旧组织名 / 旧 CRD group / `AP_`、`ap_` 前缀 / `.ap.yaml`、`.ap.json` / `ap-` 产物名 / `ap/` 路径段，命中即红。
- **重绘的物料**：10 张海报、幻灯片图表、视频预览帧、文档架构图全部重出，上屏数字只取 `docs/视频脚本.md` 的数字白名单。

## 升级前注意（破坏性）

1. **import 路径**：所有下游 `import` 必须从 `github.com/Gleamseekers/AgentPrimordia/v7/...` 改为 `github.com/Mirelth/Mirelth-Synth/v7/...`；旧 tag 与 GOPROXY 缓存不会重定向。
2. **包限定符**：`ap.NewAgent(...)` → `synth.NewAgent(...)`。只改 import 不改限定符会编译失败。
3. **配置与环境变量**：`.ap.yaml` / `.ap.json` → `.synth.yaml` / `.synth.json`；`AP_*` → `SYNTH_*`。存量部署清单与 CI secrets 需逐个核对。
4. **镜像与发布身份**：镜像 namespace 变为 `ghcr.io/mirelth/mirelth-synth*`；npm / PyPI / crates / VS Code 都是新身份，旧包无法重定向。
5. **K8s**：CRD group 改变意味着新建资源而非原地升级，HPA 与仪表盘查询需同步。

## 有意保留 / 已知问题

- git 历史、历史 commit message、16 个旧 tag 保持原样；旧 tag **未推送**到新仓库（它们的 `go.mod` 仍是旧模块路径），`v7.9.0` 是新基线的第一个 tag。
- 三个 sha256 冻结的评测题面保持原样（含旧品牌字样，属设计例外）；`gt-014` 的断言本身不是合法 base32，已登记为已知缺陷，修正走 `gap-tools-v2.json`。
- `tests/integration` 需要 `pgvector` 子模块发布 tag；`bench/soak` 吞吐门在共享负载下 flaky；Docker 镜像与本轮新分发名尚未实际发布。

```bash
go install github.com/Mirelth/Mirelth-Synth/v7/synth/cmd/synth@v7.9.0
synth version   # 7.9.0
```
